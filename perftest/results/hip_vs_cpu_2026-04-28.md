# hipfinufft vs finufft (CPU) — 2026-04-28

First end-to-end benchmark of the new HIP backend against the reference CPU
library on the same workstation, after the `hipMallocAsync` data-corruption
fix in [`ab460b76`](../../commit/ab460b76).

## Hardware / software

| | |
|---|---|
| CPU | Intel Core i9-13900 (24 threads) |
| GPU | AMD Radeon RX 9060 XT — gfx1200, RDNA4 |
| RAM | system memory; GPU has 16 GB VRAM |
| OS | Linux 7.0.0-14-generic |
| Compilers | gcc 13 (CPU), hipcc / ROCm 7.1 (HIP) |
| ROCm | 7.1 (rocm-core 6.4.3 + libamdhip64 7.1.0) |
| Build flags | `-DCMAKE_BUILD_TYPE=Release`, `-march=native` |
| Branches | `feature/hip-backend` (HIP), same checkout (CPU) |

CPU build: `cmake -B build-cpu -DFINUFFT_USE_CPU=ON -DFINUFFT_USE_HIP=OFF
-DFINUFFT_BUILD_TESTS=ON -DCMAKE_BUILD_TYPE=Release`. HIP build:
`cmake -B build-hip -DFINUFFT_USE_CPU=OFF -DFINUFFT_USE_HIP=ON
-DCMAKE_BUILD_TYPE=Release`.

## Methodology

Both backends ship a `perftest` driver with the same CLI surface
(`--prec`, `--type`, `--N1/N2/N3`, `--M`, `--tol`, `--n_runs`). For the
HIP driver we additionally pin `--method` (1 = nupts-driven, 2 = subprob).
Each cell below is the mean of 5 runs of a single transform at
`tol = 1e-6`. Times are wall-clock ms reported by the perftest event table.

Raw CSV is in [`/tmp/sweep2.csv`](#) on the run machine; the driver
script is [`/tmp/run_sweep2.sh`](#). Both are checked in below in spirit
but not by path; rerun from a clean working tree by:

```sh
build-cpu/perftest/perftest         --prec d --type 1 --N1 1000 --M 10000000 --tol 1e-6 --n_runs 5
build-hip/perftest/hip/hipperftest  --prec d --type 1 --N1 1000 --M 10000000 --tol 1e-6 --n_runs 5 --method 2
```

The HIP driver reports `host_to_device`, `makeplan`, `setpts`, `execute`,
`device_to_host`, `amortized`. The CPU driver reports `makeplan`,
`setpts`, `execute`, `amortized` (no D↔H stage — buffers are already host-side).

## Where the GPU spends its time

Single-shot type-1, double precision, M = 10M, N1 = 1000, method 2:

| event | time |
|---|---:|
| `host_to_device` | 39.3 ms |
| `makeplan` | **1.04 s**  (one-time hipFFT init dominates the *first* plan) |
| `setpts` | 5.8 ms |
| `execute` | 7.1 ms |
| `device_to_host` | 27 µs |

Subsequent plans inside the same process are ~10× cheaper, so amortized
plan cost matters a lot less when the same plan is reused.

## Takeaways

- **Crossover is around `M ≈ 10⁷`** for one-shot transforms. Below that,
  the GPU's first-plan hipFFT init (~1.07 s) and the H→D copy dominate;
  the i9 with AVX-512 finishes the whole transform before the GPU is done
  warming up.
- **Above the crossover the GPU wins by 4–8×** on this workload pair. Type 2
  shows the biggest GPU advantage at large M (8.5× at M = 10⁸).
- **Type 2 small-M is currently a regression** — HIP method 1 at M = 1e5–1e6
  is slower than CPU. Method 2 isn't compatible with type 2; whether to
  pursue an SM/subprob path for type 2 (or switch to OD method 3) is
  follow-up work.
- **Single precision speedup is smaller** because the i9 has comfortable
  AVX-512 fp32 headroom; double precision is where the GPU pulls cleanly
  ahead.
- **Plan reuse changes the picture entirely.** For iterative solvers
  (CG/LSQR-style) that call setpts+exec hundreds of times against the
  same plan, the GPU's effective speedup tracks the `execute`-only column,
  not amortized.

## Correctness — full hipfinufft ctest suite

All 287 hipfinufft ctest entries pass on this hardware. Verified by two
back-to-back runs (`cd build-hip && ctest -j 1`) of ~500 s wall each
(503 s, then 495 s) with **287/287 pass on both runs** — no flakes, no
intermittents, no order-dependent failures. Coverage includes:

- 1D / 2D / 3D
- Type 1, type 2, type 3
- All spreader methods (`auto`, GM = nupts-driven, SM = subprob, OD =
  output-driven, block for 3D type 1)
- Float and double precision (each test is parameterized over both)
- spreadinterponly mode (the test that originally caught the
  hipMallocAsync corruption bug)
- batched many-transform tests (`hipfinufft1d_test`, `hipfinufft2dmany_test`)
- `public_api_test`, `test_makeplan`, `hipfinufft_error_handling`,
  `hipfinufft_math_test`

The previously broken `hipfinufft1dspreadinterponly_test` and
`hipfinufft2d1nupts_test` (both depended on plan-reuse across
create/destroy cycles, which is what `hipMallocAsync` was corrupting)
now pass deterministically.

### Caveats on "fully correct"

What this run validates:

- Every dispatch path the test suite exercises produces results within
  the requested tolerance against the analytic reference.
- The fix in `have_pool_support` is sufficient to suppress the
  intermittent corruption — no test flaked across the suite run.

What this run does **not** validate (open follow-ups):

1. **Tolerance values much tighter than `1e-6` double / `1e-4` float.**
   Most ctests run at the 1e-4/1e-3 level appropriate for float; harder
   tolerances aren't currently part of the suite.
2. **Workloads with `M ≫ 10⁸` or `N ≫ 10⁵`.** The benchmark goes up to
   M = 10⁸ but the test suite peaks at much smaller sizes.
3. **Multi-GPU.** Only one GPU is present in this box; the
   `gpu_device_id` switching path is not exercised.
4. **Long-running stability under continuous use.** Two full ctest runs
   exercise hundreds of plan create/destroy cycles and pass cleanly,
   but we have not run a millions-of-cycles soak.

If any of those matter for your downstream use, treat this report as
"correct on the tested envelope" rather than "globally proven correct."
